# Стиль JS-кода «Звёздных шашек»

Применяй эти правила ко всему коду, который пишешь или меняешь. Проект без сборки и зависимостей: чистый JS в браузере. Комментарии и текст интерфейса — на русском.

## 0. Язык: только JavaScript, не ниже ES6

- Пишем исключительно на JavaScript. Никакого TypeScript, CoffeeScript, JSX, транспиляторов (Babel) и сборщиков.
- Минимальный уровень — **ES6 (ES2015)**. Обязательно используем его возможности вместо старых приёмов:
  - `class`, `get`/`set` — вместо функций-конструкторов и `prototype`;
  - `const`/`let` — вместо `var`;
  - стрелочные функции — вместо `function` в колбэках и вместо `self = this`;
  - шаблонные строки `` `...${x}` `` — вместо конкатенации через `+`;
  - деструктуризация, параметры по умолчанию, rest/spread (`...`) — вместо `arguments` и ручного копирования;
  - `for...of`, `Map`/`Set`, `Array.from`, `Object.assign`/spread — вместо ручных обходов и словарей на объектах, где нужны ключи-объекты.
- Новее ES6 можно (приватные поля `#field`, `?.`, `??`, `Array.prototype.includes`, `Object.entries` и т. п.), если это поддерживают актуальные версии браузеров без полифиллов.
- Код должен работать при открытии `index.html` напрямую через `file://`. Поэтому **не используем ES-модули** (`import`/`export`, `<script type="module">`) — браузеры блокируют их с `file://`. Скрипты подключаются обычными тегами `<script>` в нужном порядке.
- Сохраняем `'use strict'` в начале скриптов.

## 1. Переменные: `const` по умолчанию

- Всегда объявляй через `const`. `let` — только если переменная действительно переприсваивается (счётчик цикла `for`, аккумулятор, который нельзя выразить через `reduce`/`map`).
- `var` не используем никогда.
- Перед тем как написать `let`, проверь, нельзя ли обойтись: `map`/`filter`/`some`/`find`, тернарный оператор, ранний `return`, отдельная функция-вычисление.
- `const` не делает объект неизменяемым — изменять состояние разрешено только через методы/сеттеры владельца (см. ниже).

```js
// Плохо
let moves = [];
for (let i = 0; i < dirs.length; i++) { if (ok(dirs[i])) moves.push(dirs[i]); }

// Хорошо
const moves = DIRS.filter(ok);
```

## 2. Классы с геттерами и сеттерами

Логика игры строится на классах (`class`), а не на глобальных переменных модуля и свободных функциях.

- Внутреннее состояние — приватные поля `#field`. Наружу — только через `get` / `set` и методы.
- **Геттеры** — для чтения состояния и вычисляемых свойств (`get isKing`, `get currentSide`, `get isGameOver`). Геттер не имеет побочных эффектов.
- **Сеттеры** — для изменения состояния с проверкой инварианта (валидный тип, допустимое значение). Невалидное значение — `throw new Error('...')` с понятным русским сообщением.
- Если изменение — это действие предметной области (ход, взятие, превращение в дамку), делай метод (`makeMove(...)`, `promote()`), а не сеттер.
- Не пиши сеттер «на всякий случай»: если поле не должно меняться снаружи — только геттер (YAGNI).
- Конструктор только инициализирует объект: без DOM, таймеров и сетевых вызовов.

```js
class Piece {
  #side;
  #king = false;

  constructor(side) {
    this.side = side; // проверка через сеттер
  }

  get side() { return this.#side; }
  set side(value) {
    if (value !== 'light' && value !== 'dark') throw new Error(`Неизвестная сторона: ${value}`);
    this.#side = value;
  }

  get isKing() { return this.#king; }

  promote() { this.#king = true; }
}
```

Ориентировочное разделение ответственности для этого проекта:
- `Piece` — шашка (сторона, дамка).
- `Board` — клетки 8×8, доступ `get(r, c)`, `set(r, c, piece)`, проверка границ и игровых клеток `(r + c) % 2 === 1`.
- `Rules` / `MoveGenerator` — генерация ходов и взятий (русские правила, турецкий удар, обязательное взятие).
- `Game` — очередь хода, серия взятий, история для отмены, конец игры.
- `Renderer` / `View` — только DOM и анимации; не содержит правил.

При правке существующего процедурного кода (глобальные `let` и функции в `game.js`) переводи на классы тот фрагмент, который трогаешь, не ломая работающее. Крупный рефакторинг всего файла — только по явной просьбе.

## 3. Принципы

- **SOLID**
  - *S* — один класс = одна причина для изменения. Правила не знают про DOM, рендер не знает правил.
  - *O* — новое поведение добавляй расширением (новый класс/стратегия), а не цепочкой `if` по типам в старом коде.
  - *L* — наследник должен работать везде, где работает родитель. Если для этого нужно бросать «не поддерживается» — наследование не подходит, используй композицию.
  - *I* — небольшие узкие интерфейсы: классу рендера не нужен весь `Game`, достаточно того, что он читает.
  - *D* — зависимости передавай в конструктор (`new Game(board, rules)`), а не создавай и не ищи глобально внутри.
- **KISS** — самое простое решение, которое работает. Без лишних абстракций, фабрик и уровней ради «красоты».
- **YAGNI** — не пиши код «на будущее»: ИИ-соперник, сеть, настройки и т. п. появляются только когда о них попросили.
- **DRY** — одна логика в одном месте (например, единый источник легальных ходов). Но не склеивай похожий код, если он меняется по разным причинам.
- **Композиция вместо наследования** по умолчанию.
- **Чистые функции** там, где возможно: вычисление ходов не должно мутировать доску. Если временная мутация неизбежна — восстанавливай состояние в `try/finally`.

## 4. Паттерны (уместные здесь)

Применяй, только когда решают реальную задачу, а не ради паттерна:
- **Command** — ход как объект (`Move` с `from`, `to`, `captured`): удобно для истории и отмены.
- **Memento / Snapshot** — снимок состояния для undo.
- **Observer** — `Game` сообщает об изменениях (`onChange`), `Renderer` подписывается; правила не вызывают рендер напрямую.
- **Strategy** — разные правила хода для простой шашки и дамки.
- **State** — фазы игры (интро → игра → серия взятий → победа), если ветвлений по фазам становится много.
- **Factory method** — создание начальной расстановки (`Board.initial()`).

## 5. Антипаттерны (избегать)

- **Глобальное изменяемое состояние** — module-level `let` с состоянием игры.
- **God object** — один класс/файл, который делает правила, DOM, анимации и историю.
- **Магические числа и строки** — `8`, `'light'`, `'dark'` выносим в константы (`SIZE`, `SIDES`).
- **Анемичная модель** — класс только с публичными полями, а вся логика в чужих функциях.
- **Геттер с побочным эффектом** или сеттер без проверки, который просто дублирует публичное поле.
- **Копипаста** одной логики в нескольких местах.
- **Глубокая вложенность** — заменяй ранним `return`, guard-условиями, мелкими методами.
- **Флаговые аргументы** (`move(r, c, true, false)`) — используй объект параметров или отдельные методы.
- **Спекулятивная общность** — абстракции и параметры, которые никто не использует (нарушение YAGNI).
- **Мутация входных аргументов** без явной необходимости.
- **Тихое проглатывание ошибок** (`catch {}` без обработки).

## 6. Чек-лист перед завершением

- [ ] Только чистый JS, синтаксис ES6+, без TypeScript, транспиляторов и `import`/`export`.
- [ ] Нет `var`; каждый `let` действительно переприсваивается.
- [ ] Новое состояние — в приватных полях класса, доступ через `get`/`set`/методы.
- [ ] Сеттеры проверяют значения; геттеры без побочных эффектов.
- [ ] Правила игры не трогают DOM; рендер не содержит правил.
- [ ] Нет магических чисел/строк, дублирования и мёртвого кода.
- [ ] Комментарии на русском, в стиле окружающего кода.
- [ ] Игра по-прежнему открывается через `index.html` без сборки; логика проверена headless в Node (см. CLAUDE.md).
